ABefore you start

Once, about 10 minutes, on the laptop.

  1. Turn on two-step sign-in for GitHub, Cloudflare and Supabase. Whoever gets into one of them can change what Git2App builds.

    Open GitHub securityOpen Cloudflare securityOpen Supabase security

  2. Open Git Bash (it came with Git for Windows). Every command in this guide runs there. Get the code and its tools:

    git clone https://github.com/shubhamrkrock/PWA-to-app-converter.git
cd PWA-to-app-converter
npm ci

    No Git Bash? Install Git for Windows, then come back.

    Open Git for Windows

  3. Open your password manager and make a new note called "Git2App". The secrets below go there and then straight into the place named. Never into a chat, a file in the repo or an email.

BCreate the GitHub App people install

About 15 minutes. This is how Git2App reads a repo, read-only.

  1. Open the new GitHub App form.

    Open New GitHub App

  2. Fill in these boxes, one Copy at a time.

    GitHub App name
    Homepage URL
    Callback URL
    Request user authorization (OAuth) during installationtick it
    Webhook URL
    Webhook secret: make one here, save it in your note, then paste itnot made yet

    Screenshot slot: the top of the form, filled in.

  3. Scroll to Permissions › Repository permissions. Set Contents to Read-only. Leave everything else on No access (Metadata turns to Read-only by itself).

    Screenshot slot: Contents Read-only.

  4. Under Subscribe to events tick Push. Under Where can this GitHub App be installed? choose Only on this account. Tap Create GitHub App.

  5. On the page that opens, copy the App ID and Client ID into your note. Tap Generate a new client secret and copy it into your note too (GitHub shows it once).

    Screenshot slot: App ID and Client ID.

  6. Scroll to Private keys › Generate a private key. A .pem file downloads. In Git Bash, in your Downloads folder, change it to the format the API reads:

    cd ~/Downloads
openssl pkcs8 -topk8 -nocrypt -in {slug}.*.private-key.pem -out git2app-pkcs8.pem

    Keep git2app-pkcs8.pem until step G, then delete both .pem files.

CCreate the Workers App (only for this repo)

About 10 minutes. It lets the API start and stop builds here, so people never give Git2App access to their own Actions.

  1. Open the form again and fill in:

    Open New GitHub App
    GitHub App name
    Homepage URLhttps://github.com/shubhamrkrock/PWA-to-app-converter
    Webhookuntick Active
    Repository permissionsActions: Read and write
    Where can it be installedOnly on this account

  2. Tap Create GitHub App. Copy its App ID into your note. Generate a private key and convert it the same way:

    cd ~/Downloads
openssl pkcs8 -topk8 -nocrypt -in {slug}-workers.*.private-key.pem -out workers-pkcs8.pem

  3. In the left menu tap Install App › Install › Only select repositories › PWA-to-app-converter › Install. The address of the page you land on ends in a number: that is the installation id. Copy it into your note.

    Screenshot slot: the address bar ending in the installation id.

    Value (no slash at the end)

  2. Add the signing environment. Tap New environment, name it, then under Deployment branches and tags choose Selected branches and tags and add main. Add no secrets to it.

    Open Environments

    Screenshot slot: g2a-signing with the main rule.

Public repo, so read this (31 Oct): the repo is public for free build minutes. That means anyone can read build logs, and for one day download a release build's unsigned app. For your own Xpenstack that is fine: its web code is public on its website anyway. Before other people use Git2App, builds must move to a private repo (paid minutes) or another build service.

GThe API on Cloudflare

About 15 minutes, in Git Bash.

Claude does the file part. Send me your three addresses (website, API, GitHub App name) and I put them in the API's settings file, so the next pull has them.

  1. Get the latest code, sign Cloudflare in, and make the storage and the job queue.

    cd ~/PWA-to-app-converter && git pull
cd apps/api
npx wrangler login
npx wrangler r2 bucket create git2app-artifacts
npx wrangler queues create git2app-dispatch
npx wrangler queues create git2app-dispatch-dlq

  2. Store each secret. Run one line, paste the value from your note when it asks, press Enter. Two of them are new random values: make each here.

    State secretnot made yet
    Ticket secretnot made yet
    Signing key master key: also keep it in your note forever. Lose it and stored signing keys can't be opened.not made yet
    CommandPaste
    npx wrangler secret put SUPABASE_URL Supabase Project URL
    npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY service_role key
    npx wrangler secret put GITHUB_APP_ID App ID (B)
    npx wrangler secret put GITHUB_CLIENT_ID Client ID (B)
    npx wrangler secret put GITHUB_CLIENT_SECRET Client secret (B)
    npx wrangler secret put GITHUB_WEBHOOK_SECRET Webhook secret (B)
    npx wrangler secret put WORKERS_APP_ID Workers App ID (C)
    npx wrangler secret put WORKERS_INSTALLATION_ID Installation id (C)
    npx wrangler secret put STATE_SECRET State secret (above)
    npx wrangler secret put TICKET_SECRET Ticket secret (above)
    npx wrangler secret put CREDENTIALS_MASTER_KEY Master key (above)

  3. The two private keys are files, so they go in by pipe instead of pasting. Then deploy, and delete the key files.

    npx wrangler secret put GITHUB_APP_PRIVATE_KEY < ~/Downloads/git2app-pkcs8.pem
npx wrangler secret put WORKERS_APP_PRIVATE_KEY < ~/Downloads/workers-pkcs8.pem
npx wrangler deploy
rm ~/Downloads/*.pem

    The last line prints the API address. It should match .
